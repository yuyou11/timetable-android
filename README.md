# 时间规划表 · Android App

把你的《大一上时间规划表》做成一个常驻通知栏的 App：通知栏永远显示**此刻应该干什么**，
到点自动切换到下一格，可以在通知栏上一键关闭。

- **包名**：`com.yxz.timetable`
- **支持系统**：Android 8.0（API 26）及以上
- **源码**：本目录
- **数据格式标准**（v5）：[docs/数据格式标准.md](docs/数据格式标准.md)
  ｜ [仅课表示例](docs/example-schedule.json) ｜ [完整示例 v5（含日型配置与七套模板）](docs/example-full-v5.json)
  ｜ [完整示例 v3（老格式活样本）](docs/example-full.json)

### 功能一览

| 功能 | 在哪 |
|---|---|
| 通知栏常驻显示「此刻该做什么」 | 打开开关即可 |
| 通知栏展开后显示**明天**的日型与起床时间 | 下拉通知栏 |
| **次日预告**（明天几点起、有几节课） | 今日页中部 |
| **一键设置系统闹钟**（按明天的起床时间） | 次日预告卡片上 |
| **课前提醒**（提前 5/10/15 分钟响铃） | 设置 → 课前提醒 |
| 今日时间线（开始时间、结束时间、时长） | 今日页底部 |
| 周课表网格，**周一到周日七列**（点有课的格子，弹出详情卡看时间/教室/周次） | 课表页 |
| **周次点阵预览**（近五周 × 节数的小点阵，有课高亮；设置页可关） | 课表页周次卡片 |
| **点格子看全学期**：这一格全学期都上过哪些课，一门课一张卡（时间 / 教室 / 老师 / 周次，标出本周那门） | 课表页 |
| 课表 + 学期 + **作息模板**的导入导出 | 设置 → 数据 |
| **用 AI 生成数据**（含可直接复制的提示词） | 设置 → 数据 → 用 AI 生成 |
| **主题颜色**（蓝 / 绿两套，跟随深色模式） | 设置 → 外观 |
| 锁屏显示开关（含系统设置引导） | 设置 → 锁屏显示 |
| 手动暂停 1 小时 / 彻底关闭 | 通知栏按钮或 App 内开关 |

## 一、装到手机

1. 把 `dist/时间规划表-v1.12.0.apk` 传到手机（微信文件传输助手 / QQ / 数据线都行）。
2. 用手机上的文件管理器点开它安装。
   系统会提示「不允许安装未知来源应用」——按提示允许一次即可（这是所有非应用商店安装的必经步骤）。
3. 打开 App，第一屏是「今天」。把最下面那个 **常驻通知栏** 开关打开。

## 二、⚠️ 荣耀手机必做的五件事

**不做这几步，App 会在你锁屏几分钟后被系统杀掉，通知栏从此不再更新。**
这不是 App 的 bug，是 MagicOS 为了省电对所有第三方应用一律限制。

App 的「设置」页里已经把这五项做成了自检清单，逐条点「去开启」跳过去就行：

| # | 项目 | 操作路径 |
|---|---|---|
| 1 | **通知权限** | 设置页点「去开启」→ 允许通知 |
| 2 | **精确闹钟** | 设置页点「去开启」→ 允许。不开的话切换时间可能晚十几分钟 |
| 3 | **电池优化白名单** | 设置页点「去设置」→ 选择「允许」 |
| 4 | **锁屏显示通知** | 设置 → 通知管理 → 时间规划表 → **点「此刻该做什么」这一行进去** → 勾上「锁屏通知」。**默认是关的，不开的话锁屏上什么都看不到** |
| 5 | **自启动 / 后台运行** | 设置 → 应用 → 应用启动管理 → 找到「时间规划表」→ **关闭「自动管理」**，然后勾选：允许自启动、允许关联启动、允许后台活动 |

第 4、5 项最关键，而且**必须手动操作**——这两项都没有标准入口，
各家 ROM 的实现位置都不一样，App 只能尽量帮你跳过去，跳不到就得自己找。

### 锁屏显示有三层，别搞混

**第一层 · App 内开关。** 设置页那个开关控制的是**本 App 愿不愿意**把内容送到锁屏。

**第二层 · 系统渠道设置。** 系统还有一道总开关。它**不在应用页面上**，
而在**通知渠道里面**：

```
设置 → 通知管理 → 时间规划表        ← 应用级页面（只有「允许通知 / 置顶通知 / 类别」）
                    └ 此刻该做什么   ← 点进去，这里才有「锁屏通知 / 横幅通知」
```

> 怎么认这两页：顶部写着**应用版本号**的是应用页；
> 顶部写着**渠道名**（比如「系统默认通道」）的是渠道页。淘宝那一页就是渠道页。
>
> 这一条是用户实际反馈后改的：原来文档写的是「设置 → 通知和状态栏 → 时间规划表 →
> 打开锁屏通知」，照着走**在应用页面上根本找不到这一项**。
> App 里那个按钮现在会**直接跳到渠道页**，不用自己找。

**第三层 · 渠道是否静默。** 如果通知渠道被标成「静默通知」，
部分 ROM 会**不显示**「提醒方式」那一块，于是看起来像"没有锁屏通知这个选项"。
本 App 的渠道是 `IMPORTANCE_LOW`（不响铃不震动），所以有可能遇到这种情况。
真碰上了，可以在渠道页面把「静默通知」关掉再找。

系统这两层**没有给第三方应用任何查询或修改的接口**，所以 App 无法自动检测，
只能给你引导。设置页那一项会一直显示提示文字，就是这样来的。

另外建议：在最近任务界面（多任务卡片）里给这个 App **加锁**，防止一键清理时把它清掉。

## 三、它每天是怎么工作的

### 数据从哪来

你的规划表被拆成了三层，代码里一一对应：

| 文档里的内容 | 代码位置 |
|---|---|
| 第二节「作息基准」（第 1 节课几点到几点） | `data/Slots.kt` |
| 第三节「一周课表全景」（含周次、单双周） | `data/BuiltinCourses.kt` |
| 第四、五、六节（A 型 / B 型 / 周六 / 周日模板） | `data/Templates.kt` |
| 日型系统（哪些存在、星期几用哪套、早八优先层） | `data/DayTypePolicy.kt` |

### 日型可以自定义映射（v5）

日型在文件里用 **id "1"-"7"** 标识（1=A 型日、2=B 型日、3/4=训练日、
5/6=周末、7=休息日），名字可以用 `dayTypeNames` 段改；
「哪天用哪套」由 `dayTypeConfig` 段决定：

```json
"dayTypeConfig": {
  "types": ["1", "2", "5", "6", "7"],
  "weekdayMap": ["2", "2", "2", "2", "2", "5", "6"],
  "earlyType": "1"
}
```

`weekdayMap` 是周一到周日各自映射到的日型 —— 想恢复经典的
「周二/周四训练日」排法，把它改成 `["2","3","2","4","2","5","6"]` 即可；
`earlyType` 是「有早八优先用哪套」，省略则不区分早八。
工作日全天没课自动按休息日过，不受映射影响。

**不写这段时的默认值**保留「有早八 06:55 起 / 没早八 07:25 起」这档最核心的区分
（训练日默认闲置，映射后才启用）。老格式 v3/v4 的 `dayTypes` 段（启用/回落）
读进来会**确定性迁移**成上面的映射，行为与旧版逐日一致。
详见 [数据格式标准](docs/数据格式标准.md)。

### 节次结构因校而异

内置的一天是「上午 4 节、下午 4 节、晚上 2 节」（`"442"`，共 10 节），
但有的学校课不成对、晚上不止两节。JSON 里可以用可选的 `periods` 字段
声明自己学校的结构，**一天有多少节 = 各位数字之和**：

```json
"periods": "445"
```

意思是晚上有 5 节、一天共 13 节。第 1-10 节用内置作息，第 11 节起按晚课
节奏外推（每节 45 分钟、间歇 5 分钟、20:40 起始，到第 14 节 23:55 为止），
外推的节可以在作息模板里校准成学校的真实时间。课程 `nodes` 的合法范围
也由这个节数决定。课表页按它分行，一门课横跨多行时相邻同课格子自动合并；
不带这个字段的文件照常导入，结构保持不变。手机版与电脑版对该字段的处理
完全一致，文件互通。

### 每天现算，不是写死的

程序判断今天是哪种日型，**只看一条**：今天第 1-2 节有没有课。

- 有 → A 型日（06:55 起床、有早读）
- 没有 → B 型日（07:25 起床、08:00 黄金自习块）

所以这些情况**不需要任何额外代码就自动正确**：

- 第 8 周周三高数停课 → 自动从 A 型退回 B 型，不会误报 06:55 起床
- 第 1 周还没开课 → 全周按 B 型
- 开学前、考试周 → 跟着课表走

### 课表覆盖模板

先把作息模板铺满一整天，再把当天的课"盖"上去。
所以周三 15:55 没课时显示「自习 / 轻松跑」，有课时显示课程名 + 教室。

如果某天的晚课挤占了洗澡时间，程序会把「洗澡」自动截短到下课后，而不是出现两条打架的日程。

### 通知栏长什么样

```
┌─────────────────────────────────────┐
│ ⏱  现在：大学英语            23:14 │  ← 倒计时由系统绘制，不耗 App 电量
│   08:30–10:05 · 教一-101              │
│   第 3 周 · A 型日 · 有早八          │
│   [ 暂停 1 小时 ]  [ 关闭常驻 ]      │
└─────────────────────────────────────┘
```

> **这里曾经有一条进度条，已经删掉了。**
> 原因是它做不到「实时」：通知只在时段切换时刷新，而那一刻进度正好是 0%，
> 所以它**永远是一条空槽**。
> 而要做到真正实时，就得每分钟唤醒一次 App（一天 1440 次），
> 等于把这个 App 的省电设计整个推翻。
>
> 倒计时本来就由系统免费绘制、而且是真的实时 ——
> 进度条只是在重复这条信息，代价却是要么不准要么费电。

展开后还能看到「接着」「今天」「明天」的完整信息 —— 包括**明天几点起床**，
晚上躺床上拉一下通知栏就知道了。

### 两条通知，性质相反

| | 常驻通知 | 课前提醒 |
|---|---|---|
| 回答的问题 | 现在该干什么 | 再过 10 分钟要上课了 |
| 性质 | **状态**（一直在） | **事件**（响一次就没了） |
| 声音 | 完全静音 | 响铃 + 震动 + 弹横幅 |
| 渠道 | `now_doing`（IMPORTANCE_LOW） | `class_reminder`（IMPORTANCE_HIGH） |

为什么要分成两条？因为**上课时手机在口袋里震一下是很糟糕的体验**。
常驻那条必须安静；而提醒如果不响，就失去了意义。两者要求相反，只能分开。

课前提醒的提前量在「设置 → 课前提醒」里调（0 / 5 / 10 / 15 / 20 / 30 分钟）。

> 注意：通知渠道的重要性**创建之后就不能再由代码修改**，用户永远有最终决定权。
> 如果提醒不响，去系统设置里看这个渠道的重要性是不是被调低了。

## 四、关于省电

**没有常驻后台服务，没有轮询。**

做法是：每次只在「下一个时段切换时刻」设一个闹钟，然后 App 进程彻底退出。
闹钟响 → 醒来 → 改一下通知 → 设下一个闹钟 → 再退出。

- 一天大约醒 **20~25 次**，每次存活几十毫秒
- 通知里那个倒计时是**系统桌面自己画的**，不是 App 每秒刷新
- 空闲期间 App 进程根本不存在

对比一下：如果写成"每 30 秒检查一次"，一天就是 2880 次唤醒，而且必须常驻一个前台服务。
两者耗电量差几百倍。

**关掉开关后，这个 App 一次都不会主动醒来。**

## 五、手动关闭的三种方式

1. **通知栏上的「关闭常驻」按钮** —— 最快，锁屏界面下拉就能点
2. **通知栏上的「暂停 1 小时」** —— 临时静音，到点自动恢复
3. **App 里的总开关** —— 彻底关闭

三种方式效果一样：通知消失、所有闹钟撤销、App 完全静止。

## 五点五、不会写 JSON？让 AI 替你转

设置 → 数据 → **「不会写？用 AI 生成（含提示词）」**

会打开一个向导页，里面有三段可以直接复制的提示词：

| 提示词 | 用途 |
|---|---|
| ① 课表提示词 | 把你的课程表（截图 / Excel / 文字）转成可导入的 JSON |
| ② 作息模板提示词 | 把你的日常作息描述转成模板 JSON |
| ③ 报错修复提示词 | 导入失败时，把 App 的报错原文发回给 AI 让它自己改 |

**提示词里已经填好了你当前的学期信息**（名称、第 1 周周一日期、总周数），
所以 AI 不会在这些地方猜错 —— 这些值如果错了，整张课表的时间会全部错位。

向导页里还有**完整的操作步骤**，包括几个最容易踩的坑：

- AI 输出里混进「好的，我来帮你转换」这类开场白 → 文件就不是合法 JSON 了
- AI 用 ` ```json ` 代码块包起来 → 同样会导入失败
- **Windows 默认隐藏文件扩展名** → 你以为存成了 `课表.json`，实际是 `课表.json.txt`
- 记事本「另存为」时不选「所有文件」→ 会被强行加上 `.txt`

## 六、改作息模板（比如改起床时间）

模板定义「正常情况下这一天怎么过」。它也可以是导入的数据 —— 不用重新编译。

**完整流程：**

1. 设置页 → 数据 → **导出课表** → 选「**课表 + 作息模板**」
2. 用电脑打开那个文件，搜 `"06:55"`
3. 改掉它 —— 注意 A 型日的起床时间**同时出现在两处**，两处都要改：
   ```json
   { "start": "00:00", "end": "06:55", "title": "睡觉", "kind": "SLEEP" },
   { "start": "06:55", "end": "08:30", "title": "起床、洗漱" },
   ```
4. 传回手机 → 导入课表 → 预览里会显示「A　06:55 起床」，确认对了再点导入

**只写想改的那一种就行。** 键是日型 id（`"1"` = A 型日，其余见格式标准），
没写的日型会继续用内置模板 —— 比如只改 `"1"`，周二到周日照旧。
这比要求你把七套模板整套抄一遍友好得多。

改完之后，**通知栏、次日预告、一键闹钟三个地方会同时跟着变** ——
它们都是从模板现算的，没有谁写死了 06:55。

想恢复内置？设置页 → 数据 → 点最下面那行「作息模板：已自定义…」。
日型的名字也可以在文件里用 `dayTypeNames` 段改（最多 20 字），只影响显示。

详细的模板写法（`kind` 有哪些、`nodes` 是什么、为什么不能重叠）见
**[数据格式标准第 5 节](docs/数据格式标准.md)**。

## 七、修改课表

### 方式一：导入 JSON（不用重新编译）

设置页 → **数据** → 「导入课表」，选一个 JSON 文件。
导入前会显示预览（几门课、哪几周、有没有冲突），确认后才写入。

支持两种模式：

| 模式 | 行为 |
|---|---|
| **替换** | 文件里的课表完全取代现有的 |
| **合并** | 只加入现有课表里没有的课 |

格式见 **[数据格式标准](docs/数据格式标准.md)**，完整例子见
**[example-schedule.json](docs/example-schedule.json)**。
点 App 里的「格式说明」还能直接看写法并复制一份示例 JSON。

### 方式二：导出 → 改 → 导入

设置页 → 「导出课表」把当前课表存成 JSON，用电脑改完再导回来。
也可以点「复制 JSON」直接贴到微信里。

**导出也是备份手段**：手机丢了或者重装 App，导入一次就恢复。

### 方式三：临时停课 / 周次对不上

- **停课**：设置页 → 课程 → 取消勾选某门课（放假、调休时用），数据保留
- **周次错位**：设置页 → 手动指定周次（调课导致真实周次和日期对不上时用）

### 方式四：改默认数据

改 `data/BuiltinCourses.kt` 里的课程列表再重新编译。
只有想改「恢复内置课表」后的内容时才需要这么做。

### 三个必须知道的环境细节

1. **`services.gradle.org` 和 `dl.google.com` 在国内是间歇性可通的**（同一分钟里能 15MB/s，
   下一分钟直接拒连）。所以下载脚本里做了**多镜像兜底 + 重试**：
   Gradle 走腾讯云镜像，Android SDK 包走腾讯云镜像，Maven 依赖走阿里云镜像。
   实测截图：Google 连试三次全失败，腾讯云 7.7 秒拿下 146 MB。

2. **`GRADLE_USER_HOME` 环境变量指向 `D:\AndroidSDK\gradle-home`。**
   这是用户级环境变量，已经设好了。作用是不让 Gradle 又把近 1 GB 的依赖缓存
   建到 `C:\Users\<用户名>\.gradle` 去。
   如果哪天你发现构建突然变慢、还在重新下载依赖，先检查这个变量是不是丢了。

3. **签名文件 `release.keystore` 绝对不能删。**
   Android 用签名密钥识别一个应用的身份。这个文件一旦丢失，
   你就**再也无法更新手机上已装的这个 App**，只能卸载重装（数据全丢）。
   密码记在 `keystore.properties` 里，两个文件一起备份好。

## 八、已知限制

- **没有节假日日历**。国庆、中秋、调休不会自动识别。遇到假期请在设置页手动停掉当天的课，
  或者用手动周次功能。要彻底解决需要接一个节假日数据源。
- **日型总数上限 7 种**（id 空间 "1"-"7"），其中 "7" 恒为休息日：
  可以改名、可以改星期映射，但不能发明第八种日型（比如「考试周」）。
  真需要的话要扩 `DayType` 枚举再发新版。
- **一键设闹钟不会自动重复**。A 型日和 B 型日的起床时间不同，让用户自己在时钟应用里
  决定要不要设重复，比替用户猜更靠谱。
- **锁屏显示开关查不到状态**。系统没有提供「本应用是否在锁屏显示通知」的查询接口，
  设置页那一项只能显示提示文字，没法像通知权限那样自动打勾。
- **周六周日的模板里没有课表格子**。如果周末有临时安排的课，它会作为一条独立日程插进去，
  不会去覆盖「自由块」。
- **App 没有联网权限**，所有数据都在手机本地，不采集任何信息。

### 测试覆盖了什么

14 个测试类各守一块，数字是 `@Test` 个数：

| 测试类 | 个数 | 守住什么 |
|---|---|---|
| `data/ScheduleFormatTest` | 114 | 周次语法的全部写法 + 全部错误路径（超范围、颠倒、多余逗号、步长非数字）；「格式化 → 再解析」往返一致；解析错误信息是否指明「第几门课、哪个字段、该改成什么」；冲突检测（周次重叠报警告、**不重叠不报警告**）；内置课表导出再导入完全一致；课程名含引号/反斜杠的转义；导出字段顺序固定 |
| `data/DayTypePolicyTest` | 47 | 日型判定的三条规则（休息日 → 早八层 → 星期映射，含"停课自动退化"）；恒等配置必须与 v4 旧规则逐日一致（迁移金测试） |
| `data/TimelineEngineTest` | 42 | 周次计算（第 1 / 2 / 17 周的起始日）；课表覆盖模板、连堂合并、单双周切换、仅某周上的课；**整学期 19 周 × 7 天 = 133 天，每天的时间轴必须首尾相接、无空洞、无重叠**；人为构造的"跨午餐的怪课"，验证裁剪逻辑不会错乱 |
| `data/SlotCoursesTest` | 15 | 「点一格 → 这一格全学期的课」：命中判据是**区间重叠**（不是起点相等）、同一格跨周次的多门课、同一门课被拆成多条记录时合并、停课的课仍然列出、排序稳定 |
| `data/FormatTextTest` | 16 | 所有「用户会照着做」的格式文本，不会和真实格式脱节 |
| `data/TextDecodeTest` | 16 | 导入文本的容错（BOM、全角、粘贴带进来的杂字符） |
| `data/AiPromptTest` | 14 | 三段 AI 提示词的内容与占位（学期信息必须填对） |

| `data/SlotTimeTest` | 11 | 「节次时间」只有一个来源，别处不许再写死一份 |
| `data/TemplateImpactTest` | 11 | 「导入作息模板后，什么时候能看到变化」 |

**其中最有价值的是那两条：**

- **遍历式的不变量测试**（整学期 133 天）——单点断言只能证明"我想到的情况是对的"，
  遍历才能证明"不存在我没想到的坏情况"。
- **往返一致性测试**——用户「导出 → 改 → 导入」的整个工作流都建立在它上面。

> 另外：`ScheduleFormat.kt` 的输出是手写序列化，不是 `JSONObject.toString(2)`。
> 原因是后者在 Android 和标准 JDK 上字段顺序不同（`LinkedHashMap` vs `HashMap`），
> 会导致手机导出的文件和文档里的例子长得不一样。踩过这个坑，所以加了一条测试守着它。
