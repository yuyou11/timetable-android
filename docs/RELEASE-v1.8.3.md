# v1.8.3 · 周课表扩展到七天

首个公开版本。v1.8 / v1.8.1 / v1.8.2 都没有对外发布过，所以这是第一次发布。

---

## 这是什么

一个常驻通知栏的课程表 App：通知栏永远显示**此刻应该干什么**，到点自动切到下一格。

它和普通课程表的区别在于，**课表和作息排在同一条时间轴上**。所以它不只知道你几点有课，
还知道你几点该起床、几点能吃饭、几点该睡觉 —— 上课和自习、吃饭、训练、睡觉是互相挤时间的，
排在一起才能看清楚一天到底还剩多少空。

**完全离线**：没有申请网络权限，不联网、不上传任何数据。你的课表只存在手机本地。

---

## 下载与安装

下载本页附件 `时间规划表-v1.8.3.apk`（4.24 MB），支持 **Android 8.0 及以上**。

1. 把 APK 传到手机（微信文件传输助手 / QQ / 数据线都行）
2. 用手机上的文件管理器点开它安装。系统会提示「不允许安装未知来源应用」——
   按提示允许一次即可，这是所有非应用商店安装的必经步骤
3. 首次打开会让你选：**用内置示例课表** 还是 **从空白开始**

想用自己的课表就选「从空白开始」，然后到「设置 → 数据」导入，或用内置的 AI 向导生成
（它会给你一段可直接复制给 ChatGPT / DeepSeek 的提示词，把你的课表截图或文字丢过去就行）。

> 已经在用旧版本的话，**直接覆盖安装**即可，签名一致，课表数据不会丢。

## 本版内容

### 修复：日型标签会说假话

如果你把工作日统一成同一套作息（用 `dayTypes` 把工作日都回落到 A 型模板），
界面会在**没有早课的日子**也标上「A 型日 · 有早八」—— 那是一句假话。

根子是标签把两件独立的事焊在了一起：

- **用哪套模板** —— 由你的 `dayTypes` 配置决定
- **今天有没有早八** —— 由当天的课表决定

默认配置下这两件事正好等价（A 型日就是有早八的日子），所以一直没暴露。
一旦允许"工作日统一用 A 模板"，它们就分开了。

现在标签会分开说：

| 情况 | 显示 |
|---|---|
| 真有早课 | `A 型日 · 有早八` |
| 用了 A 模板但当天没早课 | `A 型日` |
| 周末 | `周六` / `周日` |

周课表页那个小标签同理：星期二从「早八」改成「A型」。

### 日型可以裁剪了（数据格式 v3）

引擎能算出六种日型，其中两种是「周二力量A」「周四力量B」——
它们来自一份具体规划表里的训练安排，**不是通用规律**。
没有训练安排的人看到这两套模板只会困惑：周二到底按哪套走？

现在可以在 JSON 里用 `dayTypes` 段决定**哪几种真的会被用到**：

```json
"dayTypes": {
  "enabled": ["A", "B_NORMAL", "SATURDAY", "SUNDAY"],
  "fallback": "B_NORMAL"
}
```

不在 `enabled` 里的日型，那天会改用 `fallback` 指定的那一套。

**不写这段时的默认值就是上面这个** —— 也就是：

| 日子 | 用哪套 | 起床 |
|---|---|---|
| 有早八 | `A` | 06:55 |
| 没早八的工作日 | `B_NORMAL` | 07:25 |
| 周末 | `SATURDAY` / `SUNDAY` | 早上好 |

即「有早八 / 没早八」这档最核心的区分完整保留，只把训练日的细分去掉。
需要训练日的，把那两个名字加进 `enabled` 就回来了。

> 数据格式版本升到 **v3**。老文件（v1/v2）照常能用；
> 但**旧版 App 会拒绝 v3 文件**并提示更新 —— 这是故意的。
> 旧版不认识 `dayTypes`，它会照旧用六种日型跑，你会看到训练日又冒出来却不知道为什么。
> **在数据交换里，拒绝比误解好。**

顺带修了一处：设置页那行一直写着「统一的 JSON 格式（timetable **v1**）」——
格式都已经到 v3 了它还停在 v1，而没有任何测试能发现
（那段文字当时放在界面代码里，跑不了单元测试）。
现在它会自动跟着格式版本走。

### 修复：找不到「锁屏通知」在哪里

原来 App 里的说明写的是「设置 → 通知和状态栏 → 时间规划表 → 打开锁屏通知」，
但照着走**在应用页面上根本找不到这一项**。

原因是 Android 的通知设置分两层，而「锁屏通知」在**第二层**：

```
设置 → 通知管理 → 时间规划表      ← 应用页（只有「允许通知 / 置顶通知 / 类别」）
                    └ 此刻该做什么  ← 点进去，这里才有「锁屏通知 / 横幅通知」
```

> 怎么认：顶部写着**应用版本号**的是应用页；写着**渠道名**（比如淘宝那句「系统默认通道」）
> 的是渠道页。两者长得像，但不是同一层。

现在说明文字改正了，并且新增一个按钮**直接跳到渠道页**，不用自己去找。

**但要说明白：跳过去之后，那个开关仍然看不到。** 原因在渠道本身 ——
本 App 的通知渠道是「静默」（不响铃、不震动），而该 ROM 在静默渠道下
会**整块隐藏**「提醒方式（锁屏通知 / 横幅通知）」，只显示一行「静默通知」。

**那个开关的缺席 ≠ 锁屏上没有这条通知。** 这是我自己一开始搞错的地方：
用户说「设置里没有锁屏通知」，我理解成了「锁屏上不显示通知」，差点去改渠道重要性
（那会牵动整个省电设计）。实际上这是两件事 ——

- 「设置界面里没有某个开关」是**界面呈现**的问题
- 「这个功能真的没生效」是**行为**的问题

App 已经在渠道里声明了允许上锁屏（`lockscreenVisibility = VISIBILITY_PUBLIC`），
但**锁屏上到底显示不显示，还没有实测确认过**。等确认了再来更新这段。

### 课表页：周一到周日七列

原来只画周一到周五，周末有课的话在课表页看不到。现在七列齐全。

这件事不是"加两列"那么简单 —— **屏幕宽度一点没变，多出来的两列得从原来五列里挤出来。**
按常见手机算，一列从约 59dp 掉到约 36dp，格子里能放下的字从 4 个掉到 3 个。
所以配套做了几件事：

- 节次列不再写「第 1-2 节」，改成「1-2 节」（表头已经写着「节次」，不重复）
- 页面横向边距收紧，先把空白处能省的省掉 —— 这步最划算，不牺牲任何内容
- 课程名从最多 2 行放宽到 3 行：一列只排得下 3 个字，2 行 = 6 个字，
  放不下「中国近现代史纲要」这种 8 字课名
- 顶部日型提示拆成两行（工作日一行、周末一行）：中文可以在任意位置断行，
  七条挤一行会断在「早八」中间，看着像乱码

**如果你的手机屏幕比较窄，觉得字挤，欢迎开 issue 告诉我** —— 字号和行数都是可以再调的。

### 通知栏：删掉进度条

通知栏里那条进度条**从来没动过，而且一直是空的**。

原因是它只在时段切换时被刷新，而那一刻进度正好是 0%：

```
刷新时刻 = 这一格的开始时间  →  进度 = (现在 − 开始) / 时长 = 0
```

要做到真正实时，就得每分钟唤醒一次 App（一天 1440 次），
而这个 App 的省电设计正是「不用前台服务、不轮询、只在切换点醒一次」。

**倒计时本来就由系统免费绘制，而且是真的实时**（就是通知右上角那个数字）——
进度条只是在重复这条信息，代价却是要么不准、要么费电。所以删掉。

### 修复：导入作息模板后「看不到变化」

导入一份**只改了 A 型日**的模板时，App 提示成功，但主页毫无反应 ——
因为导入那天是周二，用的是 B 型日，而这份文件根本没改 B 型。

功能其实是对的（A 型日的起床时间确实从 06:55 变成了 06:50），
只是要**等到周三**才看得见。问题出在反馈：App 只说了「成功」，
没说「今天看不到，哪天才能看到」。

现在导入作息模板后会明确告诉你：

- 改了哪几种日型
- **今天会不会变**
- 如果今天不变，**下一次生效是哪天**

判定用的是和引擎同一套规则（按「今天第 1-2 节有没有课」现算），
所以停课、调课、放假的时候它给出的日期也是对的。

### 修复：导入非 UTF-8 文件时会静默变成乱码

**如果你的课表文件是用 Windows 记事本编辑过的，很可能就踩到这个坑。**

原来导入时读文件的那行代码是 `readBytes().toString(UTF_8)`。
问题在于：这个写法**对任何字节都不会失败** —— 遇到解不出来的字节，
它会悄悄塞一个 `�` 进去，而不是报错。

于是文件存成 GBK（记事本里的「ANSI」）时会这样：

1. 课名全部解成乱码「˼������뷨��」
2. 但 JSON 的大括号、引号、键名都是 ASCII，语法照样合法
3. **导入成功，一声不吭** —— 预览框只显示「课程：24 门」，数量是对的

要过很久你才会发现课表里的课名全毁了。

现在这条路被堵上了：编码不对会**明确报错**，并告诉你怎么改。同时修的几个相关问题：

- **带 BOM 的文件**（记事本「另存为 UTF-8」会加）原来会报
  「A JSONObject text must begin with '{'」，现在会自动处理，直接就能导入
- **选错了文件**（截图、Word、压缩包）原来会弹一个被乱码撑满的对话框，
  有用信息全被挤没；现在会说「这个文件不是文本文件」并给出下一步
- **导入预览现在会列出前几门的课名**，而不只是报个数字 ——
  数量对不代表内容对，预览得给能暴露问题的信息
- 导入失败时会告诉你**具体原因**（没权限 / 网盘文件没下完 / 文件太大），
  不再一律是「读取失败，或者文件是空的」

### 内置课表换成通用示例数据

内置的示例课表换成了虚构的理工科大一课表，19 门课 + 六套作息模板。
它同时是一份**写法范本**：四种周次写法（`2-4,6-17`、`3,5,7,9`、`3-17/2`、单点）
都能在里面找到实例，照着改自己的课表最直观。

## 两个设计要点

**日型是算出来的，不是写死的。** 判断依据只有一条：**今天第 1-2 节有没有课。**
有 → A 型日（06:55 起），没有 → B 型日（07:25 起）。

这条规则的好处是，**停课、调课、开学前那一周、国庆放假，全都不用做任何特判就自动正确**。
如果按「周一 = A 型」那样写死，国庆放假时它会照样在 06:55 叫你起床。

**省电优先。** 不用前台服务、不轮询。只在「下一个切换时刻」排一个精确闹钟，
其余时间 App 完全休眠。通知栏里的倒计时由系统绘制，不消耗 App 电量。

## ⚠️ 国产 ROM 必读

**小米 / 荣耀 / 华为 / OPPO / vivo 等机型需要手动放行后台权限**，否则锁屏几分钟后
App 会被系统杀掉，通知栏从此不再更新。

这不是 App 的 bug，是各家 ROM 为了省电对所有第三方应用一律限制。App 的「设置」页
已经把这几项做成了自检清单，逐条点「去开启」跳过去就行：

| # | 项目 | 说明 |
|---|---|---|
| 1 | 通知权限 | 不开启就没有通知栏 |
| 2 | 精确闹钟 | 不开的话切换时间可能晚十几分钟 |
| 3 | 电池优化白名单 | 不开会被系统限制后台 |
| 4 | 锁屏通知 | **荣耀默认关闭**，不开锁屏上什么都看不到 |
| 5 | 自启动 / 后台运行 | 需关闭「自动管理」再逐项勾选 |

第 4、5 项最关键，而且**必须手动操作** —— 这两项没有标准入口，各家 ROM 位置都不一样。

## 已知限制

- **没有节假日日历**，国庆中秋调休需要手动停课（在设置里把那天有课的课程关掉即可）
- **日型只有固定的六种**，可以裁剪启用哪些（见上文的 `dayTypes`），但不能新增类型
- **日型策略只能在 JSON 里配**，App 内没有编辑入口
  （但设置页的「恢复内置作息」可以把它一起重置回默认）
- **课程必须挂在节次上**，无法表达非标准时间的课（比如"19:30 到 20:50"这种）
- **App 内不能手动加课**，只能通过导入 JSON 或用 AI 生成向导
