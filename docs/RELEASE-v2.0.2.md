# v2.0.2 闹钟渐强改成「前 3 秒升满，之后不变」

这一版只动一处：**响铃的音量曲线**。旧曲线是 20 秒里从 15% 慢慢爬到 100%，
实际听感是「响是响了，但一直不大」——尤其是铃声本身偏轻的时候，
人已经醒了在等它变响，闹钟却还在慢慢磨。现在改成 3 秒升满，之后保持不变。

## 一、音量曲线

| | 之前 | 现在 |
|---|---|---|
| 起步音量 | 15% | **25%** |
| 升到满音量用时 | 20 秒 | **3 秒** |
| 满音量之后 | 已在 20 秒后停 | **立即停手**，不再重排刷新 |
| 刷新间隔 | 250 ms（12 档） | **100 ms（约 30 档）** |

三点说明：

- **不从 0 起。** 0 起步的前几百毫秒等于没声音，用户会以为「闹钟没响」；
  循环铃声从 0 出来的第一声也很突兀。25% 是「听得见、但不吓人」的位置。
- **刷新间隔跟着缩短。** 3 秒里如果还按 250 ms 走，只有 12 档，
  能听出「一格一格」涨上去的台阶；100 ms 约 30 档，听感上是连续的。
- **满音量之后不再定时刷新。** 以前 20 秒内一直在写音量值；现在到 1.0 就停，
  少一串无意义的定时任务。

## 二、曲线挪出了 `AlarmRinger`

算法从 `AlarmRinger.kt` 挪到新的 `data` 无关文件 `AlarmVolume.kt`（纯计算，
不 import 任何 `android.*`）。

原因是测试：`AlarmRinger` 是个 `object`，类初始化时就 `Handler(Looper.getMainLooper())`，
在电脑上的单元测试里那一行直接抛 `Method getMainLooper not mocked` ——
曲线写在里面，就一条测试都跑不了，等于这段行为长期没人守。
挪出来之后 `AlarmVolume.at(ms)` 可以直接调，配套 6 条测试钉住：
起步不是静音、3 秒内一路上涨、**3 秒时正好 100%**、之后 5 秒 / 1 分钟 / 10 分钟仍是 100%、
越界时间不越界。

响铃本身（MediaPlayer、音频焦点、WakeLock、自动停）仍然要真机，
这条曲线是其中唯一能在电脑上完整验证的部分。
