# 《时间规划表》数据格式标准

**标识**：`timetable`
**当前版本**：2
**编码**：UTF-8
**文件扩展名**：`.json`

> **版本历史**
> - **v1** — 课表 + 学期设置
> - **v2** — 新增可选的 `templates` 段（作息模板）。
>   **没有改动 v1 的任何字段**，所以 v1 的文件在 v2 的 App 里照常能用。

---

## 0. 这份标准是干什么的

它定义了一份「时间规划表」长什么样，让它可以在不同地方之间搬运：

```
手写 / Excel 转换 / 别的程序生成
              ↓
       timetable JSON
              ↓
    App 导入 → 本地存储 → 时间轴引擎 → 通知栏
              ↓
        App 导出 → 备份 / 分享 / 手改后重新导入
```

**判定标准只有一条**：任何人拿到一份符合本标准的文件，都能不借助这个 App 恢复出完全一样的时间规划。

标准里有两种东西，它们回答的问题不同：

| 段 | 回答的问题 | 变化频率 |
|---|---|---|
| `courses` | 学校规定我**必须**在什么时间、什么地方 | 每学期一次 |
| `templates` | 没人管我的时候，我**打算**怎么过这一天 | 想改就改 |

这两者合起来才是一条完整的时间轴：模板先铺满一整天，课表再盖在上面。

> 本文档是标准的**说明**。真正的权威实现是
> `app/src/main/java/com/yxz/timetable/data/ScheduleFormat.kt`。
> 两者不一致时以代码为准，并且要改文档。

## 1. 顶层结构

```json
{
  "format": "timetable",
  "version": 2,
  "term": { ... },
  "courses": [ ... ],
  "templates": { ... }
}
```

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `format` | string | ✅ | 固定为 `"timetable"`。用来在导入时一眼认出「这不是本 App 的文件」 |
| `version` | integer | ✅ | 格式版本，当前为 `2` |
| `term` | object | ❌ | 学期设置。省略时保留 App 里原有的设置 |
| `courses` | array | ❌ | 课程列表 |
| `templates` | object | ❌ | 作息模板（v2 新增）。省略时保留 App 里原有的模板 |

### 两条规则

**① 三个内容段（`term` / `courses` / `templates`）之间是独立的：不写 = 不要动它。**

永远不要把「我省略了」理解成「我要清空」—— 那会让你的一次误操作毁掉用户的全部数据。

所以下面这份文件完全合法，含义是「只把起床时间改了，课表一个字都别动」：

```json
{
  "format": "timetable",
  "version": 2,
  "courses": [],
  "templates": {
    "A": [ ... ]
  }
}
```

**② 但三段不能全空。**

一份 `term`、`courses`、`templates` 都没有内容的文件，导入它没有任何意义 ——
而且多半意味着用户选错了文件，或者 AI 输出的东西是坏的。这时候明确报错，
比「导入成功但什么都没变」有用得多。

## 2. `term` 段（可选）

```json
"term": {
  "name": "示例大学 2026 级 · 大一上",
  "startDate": "2026-09-07",
  "totalWeeks": 19
}
```

| 字段 | 类型 | 必需 | 默认值 | 说明 |
|---|---|---|---|---|
| `name` | string | ❌ | `"未命名学期"` | 学期名称，只用于展示，不影响任何计算 |
| `startDate` | string | ✅ | — | **教学第 1 周的周一**，格式 `YYYY-MM-DD` |
| `totalWeeks` | integer | ❌ | `19` | 总周数，取值范围 `1–30` |

### `startDate` 为什么必须是周一

整个学期的时间轴是靠「第 N 周 = 起始日 + (N-1)×7 天」推出来的。
如果起始日不是周一，每一周的边界都会错位一天，课表就整体错位。

所以这里**不接受**非周一的日期。但错误信息会直接把正确日期算好告诉你：

```
term.startDate 必须是周一。
2026-09-09 是周三，应该填 2026-09-07。
```

### `totalWeeks` 的作用

它决定了 `weeks` 的合法范围。写 `"weeks": "1-20"` 而 `totalWeeks` 是 19，会报错而不是被悄悄截断。

它也决定 App 里周次选择器的上限——换学校、换学制时不用改代码。

## 3. `courses` 段

```json
"courses": [
  {
    "name": "大学英语",
    "dayOfWeek": 1,
    "nodes": [1, 2],
    "weeks": "2-4,6-17",
    "place": "教一-101"
  }
]
```

### 字段表

| 字段 | 类型 | 必需 | 默认值 | 说明 |
|---|---|---|---|---|
| `name` | string | ✅ | — | 课程名 |
| `dayOfWeek` | integer \| string | ✅ | — | `1`–`7`，**周一 = 1，周日 = 7**。也接受 `"周三"`、`"星期三"` 这类写法 |
| `nodes` | array | ✅ | — | `[起始节次, 结束节次]`，两个整数，范围 `1–10`，且起始 ≤ 结束 |
| `weeks` | string \| array | ✅ | — | 上课周次，写法见第 4 节 |
| `place` | string | ❌ | `""` | 教室 |
| `enabled` | boolean | ❌ | `true` | `false` 表示临时停掉这门课（放假、停课时用），但保留数据 |

### 关于 `nodes`

节次是固定的 10 节，时间对应关系写死在 App 里（来自《时间规划表》第二节）：

| 节次 | 时间 | 节次 | 时间 |
|---|---|---|---|
| 1 | 08:30–09:15 | 6 | 14:50–15:35 |
| 2 | 09:20–10:05 | 7 | 15:55–16:40 |
| 3 | 10:25–11:10 | 8 | 16:45–17:30 |
| 4 | 11:15–12:00 | 9 | 19:00–19:45 |
| 5 | 14:00–14:45 | 10 | 19:50–20:35 |

**连堂写法**：第 1-2 节写 `"nodes": [1, 2]`，不要拆成两条。
中间那 5 分钟换场算在同一个时间块里，App 会显示成 `08:30–10:05` 一整块。

## 4. `weeks` —— 周次写法

这是整条标准里唯一需要发明语法的地方，因为它要同时满足两种需求：
**人手写时要短**，**机器生成时要无歧义**。

### 字符串写法（给人写）

| 写法 | 含义 | 展开结果 |
|---|---|---|
| `"3"` | 第 3 周 | 3 |
| `"2-4"` | 第 2 到 4 周 | 2, 3, 4 |
| `"3-17/2"` | 单周 | 3, 5, 7, 9, 11, 13, 15, 17 |
| `"2-16/2"` | 双周 | 2, 4, 6, 8, 10, 12, 14, 16 |
| `"2-4,6-17"` | 分段 | 2, 3, 4, 6, 7, … 17 |
| `"3,5,7,9"` | 零散列举 | 3, 5, 7, 9 |
| `"*"` | 全学期 | 1 到 `totalWeeks` |

语法可以概括成：

```
weeks   := "*" | segment ("," segment)*
segment := number | number "-" number | number "-" number "/" step
```

### 数组写法（给程序生成）

```json
"weeks": [2, 3, 4, 6, 7, 8]
```

逐周列举，不需要任何语法。从 Excel 或别的系统导出时，用这种写法最省事。

### 容错规则

用户手写时打错标点是必然的，这类错误不应该导致导入失败。所以下面这些会被自动识别：

| 你写的 | 会被当成 |
|---|---|
| `，`（中文逗号） | `,` |
| `～` `~` `—` `–` `－` | `-` |
| 空格、全角空格 | 直接删掉 |

所以 `"2～4，6－17"` 和 `"2-4,6-17"` 完全等价。

**但数字和结构错误不会容错。** `"5-2"`（起点比终点大）、`"1-20"`（超出总周数）、`"2,,4"`（多余逗号）都会明确报错。

## 5. `templates` —— 作息模板（v2）

模板定义「正常情况下这一天怎么过」。课表会盖在它上面，覆盖掉冲突的部分。

```json
"templates": {
  "A": [
    { "start": "00:00", "end": "06:55", "title": "睡觉", "kind": "SLEEP" },
    { "start": "06:55", "end": "07:10", "title": "起床、洗漱" },
    { "start": "08:30", "end": "10:05", "title": "第 1-2 节", "note": "自习 / 预习", "kind": "CLASS", "nodes": [1, 2] }
  ]
}
```

### 六种日型

| 键名 | 含义 | 什么时候用 |
|---|---|---|
| `A` | 有早八 | 当天第 1-2 节有课时**自动**使用 |
| `B_TRAIN_A` | 无早八 · 周二 · 力量 A | |
| `B_TRAIN_B` | 无早八 · 周四 · 力量 B | |
| `B_NORMAL` | 无早八 · 其他工作日 | |
| `SATURDAY` | 周六 | |
| `SUNDAY` | 周日 | |

**可以只写你想改的那几种。** 没写的会回落到内置模板 ——
所以想把 A 型日的起床时间从 06:55 改成 07:15，只需要写 `A` 这一种，
别的五种不用管。

### 每格（block）的字段

| 字段 | 类型 | 必需 | 默认值 | 说明 |
|---|---|---|---|---|
| `start` | string | ✅ | — | 开始时刻，`"HH:mm"` |
| `end` | string | ✅ | — | 结束时刻，`"HH:mm"`；一天最后一段可写 `"24:00"` |
| `title` | string | ✅ | — | 这一格显示什么 |
| `note` | string | ❌ | `""` | 补充说明，显示在标题下面 |
| `kind` | string | ❌ | `"CHORE"` | 时段性质，决定颜色。大小写不敏感 |
| `nodes` | array | ❌ | 无 | 标成「课表格子」，写法见下 |

### `kind` 的取值

| 值 | 颜色 | 用途 |
|---|---|---|
| `SLEEP` | 灰蓝 | 睡觉 |
| `MEAL` | 橙 | 吃饭 |
| `CLASS` | 蓝 | 上课 / 课表格子 |
| `STUDY` | 紫 | 自习 |
| `TRAIN` | 红 | 运动 |
| `FREE` | 绿 | 自由时间 |
| `CHORE` | 青 | 洗漱之类的杂事（默认值） |
| `TRANSIT` | 浅灰 | 路上 |

### `nodes` —— 课表格子

```json
{ "start": "08:30", "end": "10:05", "title": "第 1-2 节", "kind": "CLASS", "nodes": [1, 2] }
```

带 `nodes` 的格子是**占位符**：有课时会被整格替换成课程名和教室，没课时显示成「第 1-2 节 · 无课」。

`nodes` 是 `[起始节次, 结束节次]`，两个数都在 1–10 之间。连堂写 `[1, 2]`，不要拆成两条。

### 两条硬规则

**① 同一模板里不能有重叠。**

```json
{ "start": "00:00", "end": "08:00", "title": "睡觉" },
{ "start": "07:00", "end": "24:00", "title": "早起" }     ← 报错
```

理由：时间轴引擎遇到重叠会按「先到先得」把后面的截断。结果是**你写的某一格被静默吃掉**，
界面上看不出来，只有对着表才发现少了东西。这种「不报错的错」比直接失败糟糕得多，
所以这里必须报错：

```
templates.A 里有两格时间重叠：
  00:00–08:00　睡觉
  07:00–24:00　早起
同一时刻只能有一件固定的事。如果是想上两门课，那属于课表，不在这里写。
```

**② 没铺满一整天可以，但会提醒你。**

```
templates.A 有 2 段没排到（08:00–12:00、18:00–24:00），会被自动填成「空档 · 机动」
```

漏写通常是手滑而不是本意，所以提醒一句；但不算错误，引擎能正确处理。

### 课程永远优先于模板

即使你的模板里**完全没有** `nodes` 占位格，当天的课也会作为独立日程插进时间轴，
并把冲突的模板格子裁掉。

这是刻意的：模板回答「我打算怎么过」，课表回答「学校规定我必须在哪」。
**后者是硬约束 —— 不能让改模板成为一种让课凭空消失的方法。**

    { "start": "06:55", "end": "07:10", "title": "起床、洗漱", "note": "10 月后 06:30 恢复供电，正好接上" },

## 7. 校验规则汇总

### 会导致导入失败（错误）

| 规则 | 报错示例 |
|---|---|
| 不是合法 JSON | `不是合法的 JSON：...` |
| `format` 不是 `"timetable"` | `这不是本 App 的课表文件。format 字段应该是 "timetable"，实际读到的是 "xxx"。` |
| `version` 高于 App 支持的版本 | `文件是 v99 格式，这个 App 只认到 v2。请更新 App 后再导入` |
| 三个内容段全空 | `这份文件里 term、courses、templates 三段都没有内容，没有可导入的东西。` |
| `startDate` 不是周一 | `term.startDate 必须是周一。2026-09-09 是周三，应该填 2026-09-07。` |
| `startDate` 格式不对 | `term.startDate "2026/09/07" 不是合法日期，正确写法如 "2026-09-07"。` |
| `totalWeeks` 超出 1–30 | `term.totalWeeks 必须在 1–30 之间，现在是 40。` |
| 缺 `name` | `第 3 门课：缺少 name（课程名）` |
| `dayOfWeek` 超出 1–7 | `第 3 门课（高数）：dayOfWeek 必须在 1–7 之间（周一=1，周日=7），现在是 9` |
| `nodes` 不是两个数 | `第 3 门课（高数）：nodes 必须是两个数字，例如 [1, 2]` |
| `nodes` 超出 1–10 | `第 3 门课（高数）：nodes 的节次必须在 1–10 之间，现在是 [3, 11]` |
| `nodes` 前后颠倒 | `第 3 门课（高数）：nodes 的起始节次比结束节次大：[8, 3]` |
| 缺 `weeks` | `第 3 门课（高数）：缺少 weeks` |
| 周次超出 `totalWeeks` | `第 3 门课（高数）：weeks 的周次必须在 1–19 之间，"1-20" 超出范围` |
| 周次区间颠倒 | `第 3 门课（高数）：weeks 区间 "5-2" 起点比终点大` |

模板段的错误：

| 规则 | 报错示例 |
|---|---|
| 日型键名不认识 | `templates 里有无法识别的日型 "MONDAY"。可用的值是：A、B_TRAIN_A、B_TRAIN_B、B_NORMAL、SATURDAY、SUNDAY` |
| 模板值不是数组 | `templates.A 必须是一个数组。` |
| 模板是空数组 | `templates.A 是空数组 —— 与其不写，不如整个删掉这一段让它用内置模板。` |
| **同一模板内两格重叠** | `templates.A 里有两格时间重叠：00:00–08:00 睡觉 / 07:00–24:00 早起` |
| 缺 `start` / `end` | `templates.A 第 2 项：缺少 start（如 "06:55"）` |
| 时刻写法不对 | `templates.A 第 2 项：start "8点" 不是合法时刻，写法如 "06:55"` |
| `end` 早于或等于 `start` | `templates.A 第 2 项：end (06:00) 必须晚于 start (07:00)` |
| `start` 写成 `24:00` | `templates.A 第 1 项：start "24:00" 不是合法时刻`（只有 `end` 能写 24:00） |
| 缺 `title` | `templates.A 第 1 项：缺少 title（这一格显示什么）` |
| `kind` 不认识 | `templates.A 第 1 项：kind "NAPPING" 无法识别。可用值：SLEEP、MEAL、...` |
| `nodes` 不合法 | `templates.A 第 3 项：nodes 的节次必须在 1–10 之间，现在是 [3, 11]` |

### 只会给提醒（不影响导入）

**① 同一时段有两门课，且周次有重叠。**

```
周二第 3-4 节：「A课」和「B课」在第 5、6、7 周冲突
```

注意判断条件是「**时段相同 且 周次相交**」。下面这种情况是合法的，不会报警告：

```json
{ "name": "数据结构",     "dayOfWeek": 4, "nodes": [7,8], "weeks": "3-17/2" },
{ "name": "程序设计基础", "dayOfWeek": 4, "nodes": [7,8], "weeks": "2" }
```

同一个格子，一个占单周一个占第 2 周，互不冲突——这正是真实课表里常见的排法。

**如果只比时段不比周次，这里就会误报。误报多了用户就不看警告了，那警告就等于没有。**

**② 模板有没排到的时间段。**

```
templates.A 有 2 段没排到（08:00–12:00、18:00–24:00），会被自动填成「空档 · 机动」
```

## 7. 设计约定

这几条是「为什么标准长这样」的理由，改标准前先读一遍。

### 7.1 未知字段一律忽略

```json
{ "name": "高数", "dayOfWeek": 3, "nodes": [3,4], "weeks": "1-5", "teacher": "张老师" }
```

这里的 `teacher` 在 v2 里还不存在，**会被安静地忽略，不会报错**。

这是让格式能演进的唯一办法：将来 v3 加了 `teacher` 字段，用 v2 的人拿到 v3 文件只会少读一个字段，而不是整个导入失败。

### 7.2 版本号只增不减，遇到更新的版本要明确拒绝

如果文件是 v3 而 App 只认到 v2，**必须拒绝导入**，不能硬着头皮解析。
硬解析的后果是数据被静默截断——用户以为导入成功了，其实丢了一半内容。
**报错比悄悄丢数据好得多。**

v1 → v2 的升级就是这条原则的一次实践：加模板段**只新增、不改动**任何已有字段，
所以 v1 的文件在 v2 里原样能用，**不需要任何数据迁移**。
一个格式升级如果需要用户做转换，那说明升级方式选错了。

### 7.3 输出是确定性的

导出同一份规划，永远得到逐字节相同的文件。字段顺序固定为
`format` → `version` → `term` → `courses` → `templates`，
模板内部按 `A` → `B_TRAIN_A` → `B_TRAIN_B` → `B_NORMAL` → `SATURDAY` → `SUNDAY` 的固定顺序。

这条看着理所当然，实际上是踩坑之后才加的：最初用 `JSONObject.toString(2)` 生成，
结果发现 Android 的 `org.json` 内部用 `LinkedHashMap`（保持插入顺序），
而标准 JDK 版用 `HashMap`（顺序随机），**同一个函数在两个平台上产出的文件长得不一样**。
现在改成手写序列化，输出完全由自己控制。

> 教训：只要输出是给人看的产物，就不要把它交给第三方库的默认行为。

### 7.4 报错要能直接照着改

错误信息不只说「错了」，还要说「改成什么」：

- 不是周一 → 把正确的周一算出来告诉你
- 周次超范围 → 把合法范围写出来
- 第几门课出错 → 报课程序号和课程名

一份 19 门课的文件报一句「weeks 格式有误」，用户根本不知道去看哪一条。

### 7.5 合并模式的判重键

导入时选「合并」，判重用的是 **课程名 + 星期 + 起始节次** 这个组合，而不是只用课程名。

原因：同一门课一周可能上两次（正课和习题课在不同时段），只按名字去重会把第二次误判成重复。

## 8. 导入行为

| 模式 | 行为 |
|---|---|
| **替换** | 文件里的课程完全取代现有课表 |
| **合并** | 只加入现有课表里没有的课，返回新增数量 |

**文件里没带 `courses` 时，这两个选项都不出现** —— 因为无事可做，
给两个长得一样的按钮只会让人以为自己在做选择。此时只有一个「应用」按钮。

`term` 和 `templates` 段同理：带了就替换，没带就保持原样。
**「没写」永远不等于「清空」。**

导入前会显示**预览**：课程数量、学期信息、**每种模板的起床时间**、以及所有冲突提醒。
**任何会覆盖用户数据的操作，都要先让他看见将要发生什么。**

导入完成后 App 会自动重排通知闹钟——规划变了，下一个切换时刻也就变了。

## 9. 版本演进

| 版本 | 状态 | 内容 |
|---|---|---|
| v1 | 可用 | 课表 + 学期设置 |
| v2 | **当前** | 新增 `templates` 段（作息模板）。不改动 v1 的任何字段；同时放宽了 `courses` 的必需性 |
| v3 | 规划中 | 可能新增：`time` 字段（不按节次、直接写 `"08:30"`–`"09:35"`）、`teacher` 字段 |

> v2 对 `courses` 的放宽是**兼容的**：v1 的文件都带课程，照旧能导入；
> 只是现在「不带课程的文件」也变得合法了。放宽限制和新增字段一样，不会破坏旧数据。

**每次新增都是可选的**，所以旧版本的文件永远能被新版本的 App 读，不需要转换工具。

### 已知限制

- **课程必须挂在节次上**，无法表达「08:00–09:35」这种不在标准节次表里的时间。
  这是刻意的取舍：课表页的网格、模板的占位格替换逻辑都建立在「节次」这个概念上，
  引入第二套定位方式会同时影响解析、引擎和界面三处。等真有需要时按第 7.2 节的规则升到 v3。
- **模板只有六种固定日型**，无法自定义新类型（比如「考试周」「假期日」）。
  真需要的话得先扩展 `DayType` 枚举，属于 v3 的范畴。
- **不含节假日信息**。国庆、中秋、调休不会自动识别，需要手动用 `enabled: false` 停课
  或改 `weeks`。
