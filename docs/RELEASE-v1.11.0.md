# v1.11.0 数据格式 v5：日型配置对齐电脑版

把手机版的数据格式引擎从 v3 升到 v5，和电脑版完全对齐 —— 同一份 JSON 文件
从此可以在手机和电脑之间随便搬。手机升到 v5 之后，电脑版 v5 导出的文件
手机能直接导入了（此前会被拒绝并提示更新）。

## 格式升级了什么

**v4：日型改用 id "1"-"7" 标识**

- `templates` 的键、日型相关字段的值都换成 id；v3 的旧键名
  （`"A"`、`"B_TRAIN_A"`…）照常接受，老文件不用改一个字。
- 新增可选 `dayTypeNames` 段：给日型起自己的名字（最多 20 字），
  只影响显示不改行为；今天页、通知栏、课表页都会跟着显示。
- `templates` 新增键 `"7"`：**休息日的模板可以自定义并随文件携带** ——
  此前它只能内置、不能导出。

**v5：新增可选 `dayTypeConfig` 段**

```json
"dayTypeConfig": {
  "types": ["1", "2", "5", "6", "7"],
  "weekdayMap": ["2", "2", "2", "2", "2", "5", "6"],
  "earlyType": "1"
}
```

「哪天用哪套」从此是配置而不是写死的日历规则：

- `types` 现存的日型（最多 7 种，`"7"` 休息日删不掉，缺了自动补回）
- `weekdayMap` 周一到周日各映射到哪种日型 —— 想恢复经典的
  「周二/周四训练日」排法，改成 `["2","3","2","4","2","5","6"]` 即可
- `earlyType` 有早八（第 1-2 节有课）时优先用哪套；省略 = 不区分早八

**兼容性（老用户什么都不用做）**：

- v3/v4 文件照常导入；旧 `dayTypes` 段（启用/回落）读取时**确定性迁移**
  成 `dayTypeConfig`，迁移结果与旧版判定逐日一致（有金测试盯着）。
- 本地存储里按旧键存的自定义配置也会惰性迁移。
- 导入文件「没写的段 = 不动」的规则不变；默认行为不变
  （有早八 06:55 起 / 没早八 07:25 起，训练日默认闲置）。

## 引擎判定（v5）

```
① 工作日全天无课                 → 休息日（客观事实，映射改不了）
② 工作日有早八且配置了 earlyType → earlyType
③ 其余                           → weekdayMap[星期几]
```

「· 有早八」的界面后缀仍然只看日历事实 —— 自定义映射后标签也不会说假话。

## 其他

- 导出升级为 v5（`dayTypeConfig` + `dayTypeNames` + 七套模板含休息日），
  与电脑版导出逐字节同构；「格式说明」页的文本与示例同步更新。
- AI 提示词升级：模板提示词改用 id 键并列出七种日型的对照表
  （名字取用户改过的），输出版本约定为 v4。
- 顺手修了一个两平台数据漂移：电脑版内置休息日模板的备注
  「晚自修」→「晚自习」，与手机版用词一致。
- `docs/数据格式标准.md` 升到 v5 完整版；新增 `docs/example-full-v5.json`
  （程序真实导出的 v5 样例，有测试保证它与引擎输出逐字节一致）。

## 兼容性

- 数据格式 timetable v3/v4/v5 全支持，读取向上拒绝 v6+。
- 本地数据自动迁移，无需任何手工操作。
