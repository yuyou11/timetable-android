# v1.9.0 无课的日子，按休息日过

数据格式标准第 4.5 节的日历规则里有一条：

> 1. **工作日全天没课 → 休息日**（引擎内部叫 `REST`）。
> 2. 有课的工作日，再看当天第 1-2 节有没有课区分 A / B 型。

第 1 条此前**只有电脑版实现了**。手机版跟进来之前，同一份课表在手机上
仍会把无课的工作日按 B 型过 —— 假期里照样 07:25 把你叫起来、晚上照样排晚自习。
**本版把这条对齐了**：现在两个平台的引擎规则完全一致，
同一份课表在手机和电脑上排出同一条时间轴。

---

## 本版内容

### 新规则：工作日全天没课 → 休息日

判断依据是课表数据本身：那天（第 N 周的工作日）**一门课都没有** ——
假期、停课的周次、开学前一周、课表没排到的日子，全都自动落进休息日。
程序不认识国庆中秋，但「课表里这天没课」是数据里写得明明白白的客观事实。

那天按内置的**休息日模板**过：

| | 之前（按 B 型过） | 现在（按休息日过） |
|---|---|---|
| 起床 | 07:25 | **09:00 自然醒** |
| 白天 | 黄金自习块、上课格子 | 自由块，做点自己想做的事 |
| 晚上 | 晚自习 19:00–21:40 | **没有晚自习**，自由收尾 |
| 课程格子 | 「第 3-4 节 · 无课」 | 一个都没有 |

有课但没早八的工作日照旧 07:25，周末照旧 —— **变的只有「全天没课」的那几天。**

### 休息日不受 dayTypes 配置影响

「那天没课」是课表决定的客观事实，不是偏好，所以它**不参与** `enabled` /
`fallback` 的映射 —— 就算你把 fallback 配成了 A 型，假期也不会按 A 型过、
不会 06:55 叫你起床。

同时 `REST` **写不进文件**：`templates` 的键、`dayTypes.enabled` 都只认六种日型，
导出的文件里也永远不会出现它 —— 所以**数据格式仍是 v3**，v1/v2/v3 的文件照常能导入，
不需要任何迁移。休息日的模板也定义不了，只能用内置那套（这是刻意的：
它不是一种「安排」，而是一种「事实」）。

### 界面上的变化

- 今日页头部：显示「无课 · 休息日」
- 周课表页的日型标签：显示「无课」（和电脑版的悬浮窗一致）
- 通知栏、次日预告、一键闹钟：跟着休息日模板走，假期里的起床时间就是 09:00

### 顺手修掉的一处隐患

周课表页的日型标签原来**自己拿策略做映射**，绕过了引擎 ——
真照那条路走下去，休息日会被错误地落成 fallback，假期那格标着「无早八」，
实际却在按休息模板过。现在改走引擎的统一入口（[TimelineEngine.dayType]），
把「在哪天用什么日型」收回到唯一一处。标准文档里那句话又一次应验了：
**不要在第二个地方重新实现同一套规则。**

## 已知限制

- **假期里仍有课的日子**不会被自动识别 —— 需要手动用 `enabled: false` 停课或改 `weeks`
  （休息日的判据是「全天没课」，有课就照常过）。
- 文件格式里仍只有六种日型，休息日是引擎推导出来的内部状态，文件里表达不了。
- 日型策略仍只能在 JSON 里配（设置页的「恢复内置作息」可以把它重置回默认）。
